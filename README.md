# Headless FFmpeg Music Livestream

This project builds a low-overhead, headless livestream pipeline for Ubuntu VPS machines. It loops a background video, plays tracks from a directory, updates the currently playing title on screen, and pushes the result to an RTMP destination such as YouTube, Twitch, or your own RTMP server.

## What it does

- Scans a music folder for MP3, FLAC, AAC, OGG, WAV, and similar audio files
- Builds an FFmpeg concat playlist for continuous playback
- Loops a background video forever
- Writes the current track title to a text file that FFmpeg reloads in real time
- Streams the mixed output to an RTMP endpoint
- Restarts automatically if a stream cycle crashes

## Requirements

- Ubuntu/Debian VPS with FFmpeg installed
- A background video file such as `loop.mp4`
- A music directory with audio files
- An RTMP destination URL

Install FFmpeg:

```bash
sudo apt update
sudo apt install -y ffmpeg
```

Check that `ffmpeg` and `ffprobe` are available:

```bash
ffmpeg -version
ffprobe -version
```

## Usage

You can either pass arguments directly or use a JSON config file.

Example config file:

```json
{
  "music_dir": "/srv/music",
  "background_video": "/srv/video/background.mp4",
  "rtmp_url": "rtmp://a.rtmp.youtube.com/live2/KEYHERE",
  "title_file": "/tmp/now_playing.txt",
  "playlist_file": "/tmp/music_playlist.txt",
  "font": "/usr/share/fonts/truetype/dejavu/DejaVuSans-Bold.ttf",
  "restart_delay": 2.0
}
```

Run from config:

```bash
python3 music_livestream.py --config config.json
```

Example with a local RTMP server:

```bash
python3 music_livestream.py \
  --music-dir /srv/music \
  --background-video /srv/video/background.mp4 \
  --rtmp-url rtmp://localhost/live/stream \
  --title-file /tmp/now_playing.txt \
  --playlist-file /tmp/music_playlist.txt
```

Example with a YouTube RTMP key:

```bash
python3 music_livestream.py \
  --music-dir /srv/music \
  --background-video /srv/video/background.mp4 \
  --rtmp-url rtmp://a.rtmp.youtube.com/live2/KEYHERE \
  --title-file /tmp/now_playing.txt \
  --playlist-file /tmp/music_playlist.txt
```

## How the architecture works

1. The controller scans the music directory and builds an FFmpeg concat file.
2. FFmpeg begins with the looping background video and the audio playlist.
3. A `drawtext` filter reads `/tmp/now_playing.txt` and refreshes it live.
4. The Python controller updates the title file on track transitions.
5. The final stream is pushed to RTMP.

### Example FFmpeg command generated by the script

```bash
ffmpeg -hide_banner -loglevel warning \
  -stream_loop -1 -i /srv/video/background.mp4 \
  -f concat -safe 0 -i /tmp/music_playlist.txt \
  -filter_complex "[0:v]scale=1920:1080,format=yuv420p,drawtext=fontfile=/usr/share/fonts/truetype/dejavu/DejaVuSans-Bold.ttf:textfile=/tmp/now_playing.txt:reload=1:x=(w-text_w)/2:y=h*0.12:fontsize=52:fontcolor=white:box=1:boxcolor=black@0.55:boxborderw=10:shadowcolor=black:shadowx=2:shadowy=2:line_spacing=8[video]" \
  -map "[video]" -map 1:a \
  -c:v libx264 -preset veryfast -crf 23 -pix_fmt yuv420p \
  -c:a aac -ar 48000 -ac 2 \
  -shortest -f flv rtmp://a.rtmp.youtube.com/live2/KEYHERE
```

## Systemd service

Create a service file:

```bash
sudo nano /etc/systemd/system/music-livestream.service
```

Add:

```ini
[Unit]
Description=Headless music livestream
After=network.target

[Service]
Type=simple
User=ubuntu
WorkingDirectory=/home/ubuntu/linux-ffmpeg-continuous-livestream
ExecStart=/usr/bin/python3 /home/ubuntu/linux-ffmpeg-continuous-livestream/music_livestream.py \
  --music-dir /srv/music \
  --background-video /srv/video/background.mp4 \
  --rtmp-url rtmp://a.rtmp.youtube.com/live2/KEYHERE \
  --title-file /tmp/now_playing.txt \
  --playlist-file /tmp/music_playlist.txt
Restart=always
RestartSec=5
Environment=PYTHONUNBUFFERED=1

[Install]
WantedBy=multi-user.target
```

Then enable it:

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now music-livestream.service
sudo systemctl status music-livestream.service
```

## Notes

- The script expects `ffmpeg` and `ffprobe` to be installed on the VPS.
- A `MusicBee` library is not required. Any folder of audio files works.
- If your source tracks are a mix of MP3, FLAC, and AAC, FFmpeg handles the decoding automatically.
- If you want a local RTMP server instead of a hosted platform, use MediaMTX on the same VPS and point the stream to it.
